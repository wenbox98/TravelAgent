# 10｜测试策略、用例与评测

## 测试证据分层
L0 文档/契约校验：本包实际可运行；不调用真实服务。
L1 单元测试：纯规则和合成夹具，无网络。
L2 契约/集成：受控 mock HTTP、临时 SQLite、mock sidecar、mock 模型。
L3 E2E：本地浏览器 UI＋测试后端；所有第三方仍 mock。
L4 Live：用户本机主动开启，小红书正常登录和有限请求，高德/报价真实凭证；不进入普通 CI。
L5 Release：干净 Windows 环境启动发行包，验证无需开发工具与真实功能状态。

PASS/FAIL/SKIPPED/BLOCKED 分别统计。没有凭证不是通过；不把 L3 模拟扫码截图宣传成 L4 真实登录成功。

## 自动化目录与命令（由任务创建后才可运行）
- `tests/unit/test_auth_state.py`：generation、双击、注销、过期。
- `tests/unit/test_research_budget.py`：多节点共享配额、重试、取消、恢复。
- `tests/unit/test_relevance.py`：地名、季节、重复和标题证据边界。
- `tests/unit/test_retention.py`：权限、删除、外部模型传送。
- `tests/unit/test_feasibility.py` / `test_budget.py`：明确数学算例。
- `tests/contract/`：领域 Schema、API、上游映射。
- `tests/integration/`：持久化、队列、SSE、mock sidecar 与错误。
- `tests/security/`：凭证、白名单、Origin、SSRF、恶意笔记。
- `tests/e2e/`：首次登录、粗略攻略、改选、失败状态。
- `tests/live/`：人工启动，不可自动跑网站负载测试。

开发任务建立统一命令 `python scripts/check.py --suite unit|contract|integration|security|e2e`。脚本调用当前 lock 下真实存在的工具并传递退出码，不是只有打印“成功”。普通 CI 禁止外网。

## 核心用例
详细用例 ID 与需求映射在 `contracts/test-matrix.csv`。每行必须转成测试或人工验收记录；测试记录引用实现函数，不只引用文档。

### 登录
正常扫码确认、复用本地会话、应用重启按需核实；过期 QR 不自动风暴刷新；UI 轮询 100 次上游登录核实次数不增加；同 generation 最多一个浏览器；保存 cookie 失败不能 CONNECTED；人工验证码暂停；注销后旧扫码晚到不得恢复连接；断开只清本应用专用 profile。

### 请求优化
同一 note_id 多候选只读一次；同一查询双击合并；不同账号不共享 locator；预算先预留；失败计数；取消之后不新增调用；restart 不清零；缺口补查不扫描无关酒店；清空预算不退化无限重试；仅元信息不得输出全文结论；无网络观测时返回 null 而不是 0。

### 质量与事实
合成同名地区干扰、旧季节、作者转载、图片藏有关键数字、文本仅写“见图”、低热度高信息与高热度无关内容。测试模型伪造来源、过度自信、非法 JSON、输出多余字段和自行提高预算。

### 计划与预算
fixtures/itinerary-case.json 验证 AC=510 分钟、ABCD=760、ABD=470；返程截止18:00。fixtures/budget-case.json 验证 240000～270000 分、未知费用导致 PARTIAL、房间/人数/套餐去重。系统不能因为测试值有精确结果而把真实估算变成精确承诺。

### 恢复与竞态
worker 崩溃于预留前、预留后未发出、DISPATCHED 后未存结果；旧 generation 结果晚到；两个提交同 expected_revision；SSE 断线重连；删除资料与正在写入检索结果交错。每个场景检查 SQLite 与前端一致性。

## Live 验证方法
只对用户本人愿意连接的账号运行。先完成只读/脱敏离线安全测试；操作人手动登录，不向测试脚本提供密码/验证码。

首次先用一个明确的旅行查询验证“搜索→一篇正文→出处对应”，再按小规模场景覆盖逐步检查。每次写明逻辑操作上限，达到挑战/拒绝访问立即结束；不能故意连续触发风控来测试“抗封”。验证码异常可以主要依靠 mock 注入测试，在真实出现时记录正常人工恢复。

至少记录首次连接、重复使用、正常重启、有限研究、断开连接五类真实用户流程。不可强制要求站点在测试中提供某类风险页面；未自然发生的案例标未验证，模拟测试单列。

## 请求节省与准确性评测
fixtures/research-scenarios.json 提供30条合成需求/预期约束；fixtures/research-pool.json 提供详细候选样例，开发时补齐更多人工标注的授权/合成候选。

基线=固定读前10条，策略=先排序再逐篇补缺口。仅对同一离线池回放比较，不对真实网站加倍访问。指标分开：候选排序 P@k、真实取得正文的有效率、槽位覆盖、逐条引用支持、调用数、导航和可观测 HTTP 数。

初始发布门槛：测试清单所有安全/硬约束 P0 用例通过；有效正文精确率≥80%；人工检查的关键结论引用支持率≥95%；预算超发=0；真实账号流程有证据；不能只平均达标掩盖某个危险场景。

请求节省≥30% 是离线改进目标，不是上线宣传事实。使用无缓存/允许缓存、正文可读/部分失败分组报告；不能借缓存命中组掩盖首次冷启动成本。

## 报告格式
`reports/Txx-implementation.md`：实际命令、环境、版本、PASS/FAIL/SKIPPED/BLOCKED、失败原因、产物。
`reports/live-xhs.md`：上游+patch版本、时间、OS、匿名账号标识、用户操作数、各级调用计数、结果完整度、挑战与恢复、残留进程、未验证项。
不上传真实笔记全文、二维码、Cookie、完整 trace。站点响应留证只用允许保存的脱敏元数据，原始证据可由操作人本地检查后写审核结论。
