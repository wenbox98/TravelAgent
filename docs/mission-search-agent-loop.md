## agent loop 的行为契约

每轮必须基于用户当前有效条件、选择、排除、相关已审核来源和真实工具反馈决定下一步，并记录“为什么做这一步”和“还缺什么”。循环至少具备以下动作：

1. 识别目标和未知条件，先给可讨论方向，不用人数、预算、日期问卷阻塞首次研究。
2. 正面搜索目的地、行程、具体玩法与主要路线；侧面搜索交通连接、住宿片区、相邻地点、季节/雨天替代、体验取舍与避坑。侧面搜索必须由内容缺口驱动，不能仅换同义词重复同一查询。
3. 评估候选相关性、已有覆盖、重复和正文完整性，选择值得读的正文；搜索元数据不可冒充正文证据。
4. 提取并独立审核正文。单条非法信息隔离并留下诊断，不擅自修改为合法事实；已有效信息与前面正文成果保留。单篇失败应允许读不同候选或带明确缺口生成可用结果，不让单篇无谓终止整轮。
5. 根据已获得的信息重新评估缺口、冲突和路线可行性，决定继续读同次搜索候选、换侧面查询、利用缓存、生成/修订攻略或向用户提出真正必要的问题。不能退化为固定“搜索一次→模型两次→结束”的脚本。
6. 输出可用攻略：每天具体怎么玩、顺序与时间弹性、交通衔接、住宿片区推荐与取舍、选中/排除/替代方案、来源与时效及未解决项。未知要清楚，不编造来填格。
7. 按用户选择或自由输入继续收窄；预览取消不改采用版，采用须实际保存，导出须对应采用版。只有目标已满足、用户取消或明确退出原因时结束；用尽搜索/正文后还应判断已有材料能否完成攻略。
