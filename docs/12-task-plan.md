## 里程碑
M0：T00～T01，离线工程与契约可验证。
M1：T02～T04，小红书正常登录、只读访问、少请求研究；需 G0/G1 实测门禁。
M2：T05～T07，RAG、粗略攻略、多轮修改、时间和预算规则。
M3：T08～T09，高德/报价状态与完整工作台。
M4：T10～T11，质量报告、干净Windows发行验收和开源准备。

## 可并行与不可并行
测试夹具、静态页面和纯预算函数可在契约稳定后并行，但先合并接口约定。小红书真实账号访问必须串行，同一个账号不能让多个编码Agent并发试接口。没有账号的远端Codex可以写代码、跑mock，不要把会话凭证转交远端去消除阻塞。

## 完成判定
“创建了文件”“模型认为合理”“服务返回200”都不是完成。报告必须给出指定输入的可复现结果、边界错误处理、真实测试命令、未运行项目，以及下一步的明确文档路径。

## v1.1 PoC 执行说明
在完整工作台前，先把 T02～T05 当作“小红书研究 PoC”独立里程碑验收：本地连接、受控搜索/详情、Evidence、SQLite 复用和增量补搜。CLI 足以完成该里程碑；Electron/Vue 不应成为数据通路验证的前置条件。

用户指定T02分支为`feature/xhs-readonly-sidecar`。顺序为：上游审查 → 自有Fake只读sidecar → 经确认的登录生命周期 → 真实读取适配 → 研究循环 → 经单独授权的低访问量smoke。T02结束停止，不跳到T03。真实用户数据、浏览器profile、session/token、`.env`、真实SQLite与原文不得提交。
