# 09｜安全、隐私与开源发布边界

## 开源不等于数据无条件开放
本项目免费开源代码，不附第三方攻略全文或受限向量集。使用者登录自己的账号，不等于授予本项目任意采集、云处理、分发权；不同用途依据需分别确认。这里是工程风险管理，不是法律意见。

用户尚未指定代码许可证。建议提交 Apache-2.0 许可提案，由仓库拥有者决定后再加入正式 LICENSE。若希望禁止所有下游商用，那是额外用途限制，与 OSI 开源定义的“不得限制商业领域”要求不同；不能混写“Apache-2.0 但禁止商用”。不因用户说自己不商用而自动替他施加下游限制。[S16]

上游代码许可与内容权利分开审查。固定版本保留 NOTICE、版权与 patch 记录，发布前完成依赖许可证扫描。上游功能自述和“过去没封号”不是本产品安全保证。[S01]

## 威胁模型
保护对象：账号会话、API key、精确地址、用户计划、受限来源内容、本机文件和网络。
主要威胁：恶意笔记提示词、外部网页访问 localhost、上游写工具被误调用、日志泄露、并发扫码与注销竞态、恶意链接 SSRF、篡改下载包、越权访问本机文件。

## 必须实现的控制
- 本应用与 sidecar 都仅监听 loopback；同源/Host/CSRF/鉴权检查；禁用公开 MCP 和任意工具入口。
- 上游 token 从进程环境或受控管道传入，不作为命令行参数、URL、前端配置或模型上下文。环境仍可能被同用户进程读取，不能承诺全能隔离。
- 专用浏览器 profile 不复用、不导出用户其他浏览器凭证。默认诊断不打包 profile、数据库原文、cookies 或二维码。
- 读取笔记时只给模型清洗后的必要内容，外部来源标为不可信数据。文章中的“忽略系统/访问这个URL/发送账号”不能产生工具调用许可。
- 工具白名单和参数检查由程序实现；模型请求超预算直接拒绝；写行为路由不存在。
- 网址只允许按任务需要和来源规则访问，阻止非 http(s)、本机文件、内网/云元数据地址、重定向至禁止目标、DNS rebinding。二维码图片只来自受控 sidecar，不变成通用图片代理。
- 日志源头删除 Cookie、Authorization、xsec_token、URL 查询串、手机号等；异常字符串也脱敏。不要先把原始日志写盘再做“导出脱敏”。
- 下载资源锁定来源、SHA256 和平台；校验失败停止，不关闭系统安全功能。静默绕过签名/SmartScreen 不是解决方案。

## 数据推理与模型
用户配置云模型时说明哪些资料会发送。来源不允许外部模型处理时使用允许的本地处理能力或显示无法分析；不能仅因为推理失败改发另一家服务。

关闭外部链路追踪和遥测默认值，尤其不得把 tool outputs 自动上传到公共 tracing 服务。LangGraph checkpoint 不是日志豁免区，必须经过同样的数据策略。

## 反爬相关边界
性能优化允许：少搜、先筛后读、去重、合法缓存、单会话串行、停止重试、取消无用任务。目标是减少访问负担。
不实现：验证码绕过或外包解码、账号池、IP轮换、代理池、反检测指纹伪装、伪造请求签名、突破登录/访问权限。平台要求人工验证就暂停，正常完成后继续。

不宣传“不会封号”“开源个人使用没有风险”“某固定间隔绝对安全”。

## 供应链
候选上游 lock 不是批准分发。T02审查依赖、写接口、日志、浏览器启动参数、下载源、自动更新和配置；不直接复制上游技能的整套权限。

release manifest 包含本项目 commit、上游 commit、patch hash、依赖锁 hash、构建平台、产物 hash、测试报告和许可清单。自动更新先核验 manifest 再替换；首版可只提示有新版本，不自动下载执行。

## 安全报告
新增 SECURITY.md，说明如何报告漏洞，不让报告者公开上传 Cookie/完整日志。复现用合成数据；账号相关问题仅提供脱敏错误码和运行环境。
