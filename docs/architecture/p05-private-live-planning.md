# P05 正常私人规划入口与契约

当前主入口继续使用 8768 和 `scripts/product_preview.py`。活动库仍为 `.local/p04-preview/preview.sqlite3`，schema 15，无数据库迁移；新静态目录 `.local/p05-web`。旧数据库、P04 草稿/采用版和历史授权不覆盖。备份见本机 `.local/p05-backup`，不提交运行数据。

## 运行链路

普通新建保存当前输入，不继承历史测试条件。多个同目的地、同 scope 的研究按 research_id 排序合并可用引用；读取仍走 `PreviewService._cache` 的政策、有效期、grounding 与审核检查。资料不足时只有显式 research 动作才创建 `preview_jobs`。复用正常 `ResearchService` 的 v3 提取和独立运行时上下文审核，不使用历史专项或人工接纳脚本。

新材料完成后显式加入当前旅行，再选活动、生成建议、预览/取消/采用。材料加入不覆盖采用版。模型任务只提交提议，不写草稿；旧 revision、取消和重启使任务失效。研究部分成果和失败记录保留。

`materials` 把已审核路线/体验引用投影为短地点候选，保留条件、引用 ID 和作者计划/历史经历等性质。整个日段不会作为 POI。必要时同一次规划响应可用 `grounded_activities` 选择已提供引用中的短地点名；程序检查逐字关系、正向上下文、引用范围并分配稳定 ID。有效 ID 不等于事实已经外部核实。名称改写成为用户输入，不能继续冒充来源支持。

已有两项来源支持活动且未发现区域范围冲突时不再开启研究。P05 研究满足同一条件后可提前停止，内部原因 `ACTIVITY_CANDIDATES_READY` 与完整证据充足分开，原 Coverage 缺口继续存在。明确要求市区而来源条件描述从市区出发时，展示范围待核实，并阻止将活动数量当作充分条件；这是有限上下文检查，不是城市边界判定。历史 G0/G1/G3 不变。

## 显式契约变化

- `PlanCreate.validation_trip` 仅标本次开发验收；不表示合成，不成为长期偏好。
- `PlanAction` 增加 research、adopt_research、use_activities；沿用同源认证、幂等键、revision。
- `Activity` 增加活动说明和来源性质；`PlanDraft` 增加可接受步行和有限改选指令。
- `PlanView` 增加真实候选、引用、研究进度、本批额度和可用状态；GET 只读不派发。
- 规划响应可包含受支持短地点选择，随后仍执行既有预约、时间、交通、引用审核。地图总额度允许 10（本批）或 16（历史 P03），不会转移旧计数。
- `domain.schema.json`、`openapi.yaml` 由既有导出工具同步。没有新增权限表或另建同义任务框架。

## 本批授权及出站数据

固定持久账本 `p05-private-live-planning`：连接 1、搜索 1、详情 2、所有模型 6、地点 6、路径 4；规划模型任务另限最多两次。第一次主动操作绑定唯一旅行，重新建旅行、进程或复制库均不重置。模型配置必须匹配原配置，120 秒响应等待、180 秒单次总截止，无自动重试、连通性测试、外部排名、命名附加请求。

私人规划 payload 仅含当前枚举/时间约束、活动和至多两篇已审核必要引用。再次检查来源模型政策和原联系方式过滤，每篇每次最多 6000 字。不序列化自由输入中的私址、起终点、地图值或凭据。原文仅去往既定 DeepSeek；用户私人用途许可不等于作者/平台授权。

主服务出站只允许高德指定路径，且须处于 AmapAdapter 的传输窗口；模型子进程只允许既定 DeepSeek 单次请求。普通浏览器仅研究子进程可载入，保留普通配置。Python 网络审计不覆盖浏览器进程；浏览器由已有 context observer 单独计量，不把 Python 零请求说成浏览器零流量。统计只记录计数，不记录 URL、头或正文。

## 地图与时间

真实模式使用 AmapAdapter，合成 adapter 只服务明确合成旅行。本批只查询来源支持的公共活动地点和当前采用顺序的相邻边；未确认私址不派发。模式来自明确意向，公交空结果不换驾车。日期未知不代填日期。道路耗时不计入公交时间，明确接受的步行可计入步行参考。

地点确认后收起备选，再展开仅读本机。A→B 不代替 B→A，端点、模式和日期变化使对应结果失效。地图原始数据、坐标、耗时不写数据库、日志或恢复文件；仅保留用户输入、凭据以外的授权计数。重启后显示过期，禁止自动重查。

移动秒数不向下取整，程序组合停留区间、休息与已知移动；未知移动不按零计算。预约区分确定冲突和可能迟到。首项 10 点仅来自本次输入；第二天不套用第一天锚点。跨夜窗口须明确提供，最晚返回和未核实接驳继续保留。建议被采用后仍是 AI_PROPOSED。
