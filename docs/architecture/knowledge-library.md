# 私人旅行资料库（关键词检索）

## 迁移前依赖核对

|入口|当前依赖|本批处理|
|---|---|---|
|PreviewService._cache / Evidence 读取|原文、BodyBlock、candidate/attempt、历史审核及精确定位|保留原校验；清原文后不再宣称能重放|
|旧活动复用 / discovery / local_contents|原正文与地点定位；旧采用版不能单独作证|新增独立知识引用，旧路径不降级|
|模型规划|原 Evidence 或地点上下文|知识活动走独立最小输入，并禁止正文/块/旧模型输入读取|
|删除 sources / source_contents|会级联删除审核、候选、研究关联|清缓存禁止使用这些删除入口；保留身份并置清理标记|
|context_review_runs / extraction_candidates|当前库仅保存有限提议、引用与条件，非完整片段目录|保留审核身份，清理检查等价全文副本|
|preview_jobs.request_json|当前库包含有限规划引用、草稿及历史研究需求|独立检查正文副本；不作为知识读取兜底|
|调用账本 / profile|独立数据|整理、清原文和删除知识均不得改变|

迁移前已用 SQLite backup 保存主库，并备份当前静态目录至本机忽略目录。逻辑清理仅承诺指定副本当前应用数据，不擦除历史备份、磁盘物理残留。历史备份不用于知识兜底。

关键词模式为 LOCAL_KEYWORD_RETRIEVAL，向量 NOT_IMPLEMENTED。采用持久中文二字词索引与有界排名；不依赖 trigram 的短词 MATCH。SQLite 官方说明见 [FTS5](https://www.sqlite.org/fts5.html)。


## 契约与实现

数据库16新增版本化卡片、词索引、原文可用性和来源撤销表；Library 启动时本地检查并创建 FTS5 索引。源内容身份行保留，原文显式清理置 USER_CLEARED 并移除文字载荷与块；意外内容/块修改触发 UNEXPECTED_CHANGE。数据库无降级，回滚代码不得恢复旧预算。

`knowledge/organize.py` 复用 `_cache` 和地点 `checked`；来源知识保留精确条目和所有条件，不作自由摘要。整理预览绑定内容摘要，提交时重新生成；稳定语义键幂等，改变条件生成新版本。研究成功后的本地整理不改原候选审核；采用节奏由用户单独保存。

`knowledge/store.py` 重查当前来源/策略/删除状态，校验卡片内容hash、原内容身份及历史核对。来源知识还核对原claim删除/变更；从卡片保存的节奏保留依赖，前置卡片删除/改版会阻止后续使用。多来源撤销保守使整张依赖卡失效，不删用户行程。

`knowledge/planning.py` 使用独立卡片引用，不生成假Evidence。加入仅限空的新旅行草稿；约束从新旅行取。调用前、返回后、发布事务内和采用时复查卡片及旅行修订。现有V2固定约束/事实检查保留。首次方案预览保存原草稿，取消可恢复；只在程序记录的同一取消修订、且当前输入仍逐字段相等时复用已存提议。

`knowledge/cleanup.py` 清理指定库的原文与块、旧原文chunk索引及发现上下文/完整输入副本，保留来源、内容身份、候选/审核身份、有限派生条目、采用版和全部账本。预览和执行在事务内重查；运行中的任务阻止清理。知识提交在清理之前独立持久完成，清理中断回滚。此操作不是 disconnect，也不是诊断目录或备份的物理擦除。

只承诺指定应用库的逻辑清理。保留PERSISTENT历史原文，原文保留偏好可选 PERSISTENT / READY_AFTER_ORGANIZED / SESSION；后两者仅表示整理或会话后可清理，界面明确不会自动删除，仍必须预览和确认。自动过期/会话结束删除未启用。历史备份、其他库和磁盘残留仍可能持有数据，不作兜底读取。

## 最短使用步骤

从仓库根目录运行：

```powershell
.venv\Scripts\python.exe -X utf8 scripts\product_preview.py serve --open
```

同一入口 http://127.0.0.1:8768/。打开“我的旅行资料”→“整理已有资料”选择历史旅行→预览并确认。按地区/关键词/类型检索；开发测试资料需明确勾选。建立独立新旅行，选中卡片“加入这次新旅行草稿”。如需AI，再设置普通有限许可并主动生成。生成后可预览、取消、采用；刷新和重启不自动派发。

“清理原文缓存”与“删除旅行知识/不再使用来源”分别预览影响。主库不自动清理；本轮真实删除只在隔离副本完成。
