# 私人旅行的一次提交编排

本契约替代普通首页必须依次操作许可、研究、加入资料、选择活动和生成建议的旧入口解释。旧工作台、许可和历史门禁保留在高级操作中。

普通用户输入一句旅行想法，点击「查资料并生成旅行建议」。按钮旁说明本次用途、接收方、必要资料、有限范围以及不覆盖采用版；此版本化操作本身就是本次任务的明确授权，不伪造用户勾选，不继承其他旅行许可。

## 输入与默认执行范围

`POST /api/v1/preview/automatic-planning` 使用 `AutomaticStart`：`request`、可选目的区域修正、旅行类型及 `consent=PRIVATE_RESEARCH_AND_ADVICE_V2`。必须通过原同源 Cookie、Origin、CSRF 和幂等键检查。目的区域不能可靠识别时要求修正；未知人数、预算、日期、时刻和交通不阻止先给建议。

服务器按当前天数和旅行范围选择有限上限：一两天最多连接1、搜索2、正文4、模型9；三天及以上或跨区域最多连接1、搜索3、正文6、模型13。天数未知先用较小范围。地图/embedding/报价为0，有效期一小时。模型预留为每篇最多一次提取、一次上下文审核及一次总规划，失败占用次数，不自动重试。材料覆盖足够时收窄到模型1次及零站点访问，非空缓存本身不能早停。V2显式意图与旧V1不兼容，旧客户端不能沿用较小范围的意图启动新上限。金额不能实时核算，次数上限不是费用承诺。

新许可使用现有 `research_continuations` 和 `continuation_operations`，关联原许可、旅行、目的区域、generation、任务及授权版本。结束、停止或条件变化关闭本次许可。历史用量、失败、已过期许可均不重置。

## 服务端状态与派发

迁移017新增 `planning_tasks`，持久化任务、输入版本、有限许可、研究与规划子任务、阶段、状态和幂等回执。状态读取与刷新不启动进程。显式POST后后台 `task-worker` 仅领取一次 QUEUED；重复投递由状态领取和已有任务回执阻止。同一账号已有自动任务时不再创建并行旅行研究。

链路：解析当前需求 → 重校可用缓存覆盖 → 必要时检查正常登录 → 既有 ResearchService 多轮搜索/正文/v3提取/上下文审核 → 关联本次暂定材料 → 程序投影合格活动 → 既有建议型规划worker → 原逐方案事实与约束检查 → 可比较的新建议。自动任务按建议研究覆盖评估：路线/区域与顺序、玩法取舍、停留或时长、适用交通、时令、不同内容对照及随天数调整的选择面。它是材料充分性启发规则，不是实测可行性、每天排满或文章篇数目标。每轮围绕尚缺主题使用不同关键词；默认把正文额度分到不同查询，足够即停。重复候选不重读，相同正文不重提取、不同来源高重合引用不能算独立对照，潜在冲突保留缺口；作者独立性仍未知。范围UNKNOWN保留UNKNOWN，MISMATCH不自动进入暂定组合；只接受正文支持并通过原审核的引用，不从标题或模型记忆造活动。

正文、定位、来源条件、作用范围、知识版本和撤销检查继续执行。资料卡、已审核证据及地点提及不混同；历史建议不是新生成。无合格可规划活动时停在具体资料缺口，不以空白占位或其他城市资料兜底。

研究总时限2700秒（含最多300秒正常登录等待），编排等待研究2850秒、监督编排3300秒，模型单请求仍120秒、外层190秒；额度模型预留和时限同步改变。预算或总时限不足保留独立合格资料与局部建议，不能标完整攻略；没有合格活动则明确阻塞。编排进程不允许直接访问模型或小红书，仍通过现有受限子进程。每个模型调用最多一次HTTP请求，读取必要内容，每来源每次6000字的过滤限制继续执行。模型不接收凭据、私址或地图返回。

## 首次配置、登录和异常

未配置模型时持久化 WAITING_CONFIGURATION，不创建额度、不联网；服务端配置完成后显式继续。已配置不再询问。登录走现有普通官方浏览器生命周期，任务进入等待登录，正常登录后继续原任务；挑战、拒绝和限流停止。没有登录状态确认不得声称已查成功。

页面就地展示查找、正文、提取、审核与整理建议阶段，不使用假百分比。真实搜索数、观察候选/去重候选、正文尝试/成功数、采信来源、每轮新增合格引用、新查/缓存区别、标题、无访问token的公开链接、取得时间、完整度和失败阶段分别展示。取得时间不是作者出行时间；模型审核也不是外部事实核实。

关闭/取消先失效任务，关闭许可并标记子任务取消。API调用之间由原worker观察失效并清理浏览器，不强制取消正在执行Playwright调用的asyncio任务。generation、当前任务和版本检查阻止晚结果进入新草稿。服务重启只恢复结果并把未完成任务记为INTERRUPTED，不重放派发。

## 补充条件与采用

`POST /api/v1/preview/automatic-planning/{session_id}` 使用 `AutomaticAction`。补充天数、驾驶、公共交通、轻松节奏、明确步行、人数/房晚、范围及硬时间要求可由确定性解析更新；不能明确解析的变化先询问，不能默默当作已落实。减少天数时旧的未锁定日序重新交模型分配，原采用版不改，预约超出新范围则要求解决冲突。

优先保留当前资料，覆盖足够时不再搜索/读取/提取；不自驾等新增条件重新评估交通适用性。超出默认范围后仅显式「继续补充研究」启动新任务，按缺口查找，关联旧用量而不重置或自动续期。锁定活动保留；新知识只能是本任务实际读取并通过原审核的来源，知识绑定和版本重新校验。新任务有自己的有限许可并累计旧用量。未确认的结果显示为新建议，预览、取消均本地；只有最终采用才更新采用版。导出继续使用既有采用版与引用核查，未采用的新结果不进入导出。

## 会话、选择与回退契约

普通主页面以会话记录、可比较方案卡、一个当前快捷问题和自由输入为入口。`POST /api/v1/preview/conversation/{session_id}` 使用 `ConversationAction`，包含旅行 revision、独立 conversation version、稳定 option/activity ID、幂等键及原同源鉴权。方案 ID 绑定任务和完整提议指纹，不能凭标题选择旧结果。文本与按钮共用同一持久化状态；选方向、排除、恢复、解释和采用不混为一个动作。

纯提问从当前通过原验证路径的引用作本地解释，标记 `LOCAL_REFERENCE_EXPLANATION`，没有模型或研究请求。不能可靠理解的修改先询问；交通、天数等可明确解析的变化和显式更新才创建有限新任务。局部选择不修改已保存模型输入或采用版；在下一次明确派发前冻结最小对话上下文，包含有效方向、方案和活动排除、最近相关用户意图、条件变化及覆盖缺口。来源事实仍走原引用集合，助手自己的解释不作为新证据。私址、凭据等输入不进入外部摘要。

活动排除先从允许活动池移除，程序再审核模型结果；与已排除方案相同的活动顺序独立拒绝，其余合格方案保留。所有原锁定、来源、范围、预算、上下文和版本检查仍执行；有效 ID 不等于事实或语义合格。选择和撤回有独立版本冲突检查，刷新与重启只恢复，不重放请求。新任务开始后旧 generation 不可提交，清空选择也不会恢复旧额度。

地图继续使用既有主动核实入口及独立许可，本次自动研究许可不包含地图请求；当前会话不会自动把真实地图返回发给模型。本轮不声称关键路段已经完成新的实站核实。

## 验证边界

测试服务器的 `--automatic-synthetic` 仅存在于 tests/helpers，生产命令没有此选项。合成适配器覆盖真实业务编排、提取审核、计数和浏览器操作；这不证明真实小红书通过。实际访问需要用户在正常页面明确发起；开发指导消息不替用户提交旅行。历史G1和私人版冻结状态不因离线链路通过而改写。


本轮专项回归与真实边界见 [登录与覆盖驱动研究报告](../../reports/P10-login-and-coverage-research.md)。最新自动研究的真实站点/模型整链仍需独立确认与官方登录，离线通过不能替代该验收。
