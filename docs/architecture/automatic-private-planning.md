# 私人旅行的一次提交编排

本契约替代普通首页必须依次操作许可、研究、加入资料、选择活动和生成建议的旧入口解释。旧工作台、许可和历史门禁保留在高级操作中。

普通用户输入一句旅行想法，点击「查资料并生成旅行建议」。按钮旁说明本次用途、接收方、必要资料、有限范围以及不覆盖采用版；此版本化操作本身就是本次任务的明确授权，不伪造用户勾选，不继承其他旅行许可。

## 输入与默认执行范围

`POST /api/v1/preview/automatic-planning` 使用 `AutomaticStart`：`request`、可选目的区域修正、旅行类型及 `consent=PRIVATE_RESEARCH_AND_ADVICE_V1`。必须通过原同源 Cookie、Origin、CSRF 和幂等键检查。目的区域不能可靠识别时要求修正；未知人数、预算、日期、时刻和交通不阻止先给建议。

服务器默认上限：连接1次、搜索1次、正文2篇、模型5次，地图/embedding/报价为0，有效期一小时。五次模型是最多两篇的提取、上下文审核及一次规划，失败占用次数，不自动重试。当前已有合格活动时，本任务收窄到模型1次及零站点访问。金额不能实时核算，次数上限不是费用承诺。

新许可使用现有 `research_continuations` 和 `continuation_operations`，关联原许可、旅行、目的区域、generation、任务及授权版本。结束、停止或条件变化关闭本次许可。历史用量、失败、已过期许可均不重置。

## 服务端状态与派发

迁移017新增 `planning_tasks`，持久化任务、输入版本、有限许可、研究与规划子任务、阶段、状态和幂等回执。状态读取与刷新不启动进程。显式POST后后台 `task-worker` 仅领取一次 QUEUED；重复投递由状态领取和已有任务回执阻止。同一账号已有自动任务时不再创建并行旅行研究。

链路：解析当前需求 → 检查可用缓存 → 必要时既有 ResearchService 搜索/正文/v3提取/上下文审核 → 关联本次暂定材料 → 程序投影合格活动 → 既有建议型规划worker → 原逐方案事实与约束检查 → 可比较的新建议。合格活动足够给有限建议就早停，不要求两个MATCH才规划。范围UNKNOWN保留UNKNOWN，MISMATCH不自动进入暂定组合；只接受正文支持并通过原审核的引用，不从标题或模型记忆造活动。

正文、定位、来源条件、作用范围、知识版本和撤销检查继续执行。资料卡、已审核证据及地点提及不混同；历史建议不是新生成。无合格可规划活动时停在具体资料缺口，不以空白占位或其他城市资料兜底。

编排进程不允许直接访问模型或小红书，仍通过现有受限子进程。模型最多一次HTTP请求，读取必要内容，每来源每次6000字的过滤限制继续执行。模型不接收凭据、私址或地图返回。

## 首次配置、登录和异常

未配置模型时持久化 WAITING_CONFIGURATION，不创建额度、不联网；服务端配置完成后显式继续。已配置不再询问。登录走现有普通官方浏览器生命周期，任务进入等待登录，正常登录后继续原任务；挑战、拒绝和限流停止。没有登录状态确认不得声称已查成功。

页面就地展示查找、正文、提取、审核与整理建议阶段，不使用假百分比。真实派发计数、成功取得正文数、新查/缓存区别、标题、无访问token的公开链接、取得时间、完整度和失败阶段分别展示。取得时间不是作者出行时间；模型审核也不是外部事实核实。

关闭/取消先失效任务，关闭许可并标记子任务取消。API调用之间由原worker观察失效并清理浏览器，不强制取消正在执行Playwright调用的asyncio任务。generation、当前任务和版本检查阻止晚结果进入新草稿。服务重启只恢复结果并把未完成任务记为INTERRUPTED，不重放派发。

## 补充条件与采用

`POST /api/v1/preview/automatic-planning/{session_id}` 使用 `AutomaticAction`。补充天数、驾驶、公共交通、轻松节奏、明确步行、人数/房晚、范围及硬时间要求可由确定性解析更新；不能明确解析的变化先询问，不能默默当作已落实。减少天数时旧的未锁定日序重新交模型分配，原采用版不改，预约超出新范围则要求解决冲突。

优先保留当前资料，足够时不再搜索/读取/提取。新任务有自己的有限许可并累计旧用量。未确认的结果显示为新建议，预览、取消均本地；只有最终采用才更新采用版。导出继续使用既有采用版与引用核查，未采用的新结果不进入导出。

## 验证边界

测试服务器的 `--automatic-synthetic` 仅存在于 tests/helpers，生产命令没有此选项。合成适配器覆盖真实业务编排、提取审核、计数和浏览器操作；这不证明真实小红书通过。实际访问需要用户在正常页面明确发起；开发指导消息不替用户提交旅行。历史G1和私人版冻结状态不因离线链路通过而改写。
