# V5 搜索 agent loop 契约

当前任务与验收以 [missionList/checkList](../mission-search-agent-loop.md) 为准。本文件说明已经实现的代码行为；不代表两轮真实内容验收通过。

## 新许可与历史兼容

普通页面新提交使用 `PRIVATE_GOAL_AGENT_V5`。一个任务共用一份持久许可和累计账本：搜索最多5次、正文最多20篇、`MODEL=null`表示无调用次数上限；实际模型请求仍逐次预留、计数、校验配置与记录诊断。缓存或假设限制只能收窄范围，不能扩大；旧V3/V4许可和旧消耗保持原样。四小时是本次许可的有效时间，不是模型次数限制；单次请求超时、取消和服务失败仍停止，不重发失败请求。

迁移019仅将 `extraction_batches.max_attempts` 的结构上界从12扩大到20，复制全部原行和原值，保留子表引用。迁移在一个事务内完成，复制期间临时关闭外键执行，提交前完整检查引用，结束恢复外键执行；失败回滚。此字段限制来源分析预留数量，不限制监督、审核和生成的模型调用总数。

真实浏览器读取器接收当前许可的搜索和正文范围，不能保留隐性的3/6上限；网络观测窗口白名单支持搜索1–5、正文1–20。旧许可仍传入原范围，不自动升级。已完成研究的知识卡更新只在当前研究来源或事实/条件/来源完全相同的活动拆分兼容迁移时刷新未锁定草稿，旧采用版保持。显式修复版本合并或已经诊断的旧浏览器上限错误时，只创建原剩余额度的续做许可，保留前驱、原到期时间、历史消耗和查询去重；任何网站验证、访问拒绝或模型服务失败都不能以此方式续做。

## 根据反馈循环研究

首次模型理解当前需求；问题或假设不写回当前条件。每轮监督输入包含当前条件、选择、排除、经过用途过滤的相关引用、缺口、剩余许可和此前实际工具结果。可选业务工具为缓存复核、来源整理、按缺口研究、生成建议、回答和已明确授权的关键衔接核实。

正面视角研究路线、日数与具体玩法；侧面视角根据缺口研究交通接驳、住宿片区、季节替代、冲突或体验取舍。程序记录查询、视角、目的缺口、决策来源、前后覆盖和实际用量；模型不得通过换同义词重复失败请求。尚缺用户要求的研究视角或内容且本次范围仍允许时，过早结束会被记录为目标守卫修正，使用当前缺口的一次不同查询，随后仍由实际结果进入下一轮监督。具体玩法查询使用实际未覆盖的命名项目；推荐查询按历史去重，不能把同一查询反复发送。

每次研究共享同一许可，使用 `research-step-` 子任务标识，允许完成一个查询后创建下一查询，同时仍禁止并行活动子任务。同一搜索列表按每篇结果重新排序、去重择读；5/20是上限，不要求用满。V5不再使用旧六轮截止；连续两步没有有效资料、条件或覆盖进展，或发现重复动作时，已有材料可生成则转入局部攻略生成，否则明确停止。服务/权限/验证失败不会被此恢复绕过。

玩法覆盖除全局经验条目外，检查主要备选项目是否有同文档、同对象的已审核具体体验引用。只有路线名字不能满足此维度。任何局部攻略仍显示缺口，材料覆盖不证明未来开放、交通可行性或当天排程已经核实。

生成后还检查建议本身的缺失天数、具体玩法支持和多日住宿片区，不能只凭 JSON 合法或材料计数宣布完成。未满足时，已有可预览建议保留，实际缺口进入下一轮监督；原剩余来源范围、去重与无进展退出仍适用。连续无进展的最后一次整理只保留明确局部结果，不无限再生成。

V5候选池优先保留锁定选择，再按来源分散选择不同的命名项目；“游客中心/景交车/抵达市区”等通用步骤留在来源路线语境中，不挤占游览玩法位置。住宿片区只从本次已审核住宿语句中逐字提取，保留原文角色、前提和引用；排除否定建议和无法识别的通用地点。选择片区必须同时引用其支持信息，排除或撤回的引用不可继续作为当前住宿建议。晚数、房间数、是否纳入费用未知，不妨碍暂定片区比较，也不变成已确认预订。

已生成的局部攻略显式续做只允许继承原许可剩余次数和原到期时间，保留所有旧授权/消耗；过期、耗尽、验证失败不借此恢复。普通页面读取在单次请求内复用已校验的相同资料，连接写入和其他连接的数据版本变化都会失效，每个新请求重新校验。

## 正文结构容错

新增引用目录v2按标点短句保留精确位置，全文每个字符仍只发送一次，独立审核读取父段与相邻短句。这样可分别审核玩法与票价，不能删去否定、主体或依赖前提。保存的v1目录按原版本完整重建，不重写旧引用、审核和采用版。ReferenceSelection契约显式允许v1/v2各自成对的prompt_version；新提取配方为reference-selection-v2.0。EXPERIENCE只表示玩法主题，GUIDE_SUGGESTION无需证明作者亲历；个人经历角色仍须明确原文依据，价格、运营与交通可行性仍严格拒绝未经核实的执行结论。

玩法主体可来自独立审核已选的同父段精确短句前提，投影为可选clause_context；位置/文本长度不能唯一对应时不建立关联。同日标题或整段路线列表不用于直接地点归因。实际玩法卡优先于同名路线卡进入候选池；缓存重分析最多两篇，按当前项目和具体玩法内容排序，不因最新资料只含“游玩”而挤掉相关正文。

模型输出的外层 JSON 与 claims 数组仍严格校验。每条 claim 独立按完整契约检查；非法topic或缺字段整条隔离，留下安全结构路径诊断，不将非法值猜改为合法事实。合法兄弟条目继续原有逐字定位与独立模型上下文审核。

任何敏感材料仍可阻断整篇；不能借隔离绕过用途边界。整篇没有有效条目时允许读不同候选，保留前面成果，不自动重发同篇、同请求。正文完整性、作者角色、适用条件与图片未分析状态保持。

## 验收边界

### 本地导出与成功问答

成功缓存问答以QUESTION_ANSWERED结束，独立于是否生成新攻略；新任务标COMPLETED，页面兼容历史PARTIAL成功记录，不改写历史状态。只有该成功原因显示已回答，其他失败继续保留具体原因。

攻略导出使用既有认证下的同源只读guide-export；读取后核对旅行、采用内容和revision，期间有变化则不下载。按钮显示准备进度、阻止重复点击并呈现错误，不自动重试或调用研究。采用版Markdown经本地Blob交给浏览器后保留足够时间再释放；页面只说已交给浏览器，不声称已经写入磁盘。原guide-download兼容端点保留，服务端仍重新核对来源，不改变安全边界或采用版。

### 问答选材一致性

`cached_travel_question_v1`使用专用问答提示，要求按当前条件比较缓存来源、保留未知和引用边界，假设的proposed_conditions为空；不能误用正文提取提示。输出拒绝保存字段名、规则类别和版本，不回显敏感原值。仅移除明确、有限的否定保证谓语，同句中的肯定保证仍拒绝；来源绑定与敏感材料阻断保持。

保证表述被拒绝时，在该字段已排除敏感信息、URL和私址后，仅在本机question-diagnostics保留命中点前后各至多60字的生成文本与七天到期标记，不保存全文或传给模型。此证据只用于定位误报，不直接采用或自动重发。敏感、URL和地址拒绝不留文本片段；私有诊断不进Git。

监督决策按许可使用至多20篇（V5）或6篇（V4）来源，缓存问答使用至多2篇相关来源。派发请求与调用前、返回后的资料校验共用按用途选择的规则，不能把V5监督的20篇上限套在两篇问答上而误报 `AGENT_MATERIAL_CHANGED`。当前到达交通、当地交通、自驾与租车条件分别传入问答；假设不写回条件或采用版。资料真实过期、绑定或版本变化仍拦截，不通过关闭校验修复误报。

离线 HTTP200合成回归通过只能证明故障链和业务工具行为。真实模型、真实小红书正文、普通页面生成、取消预览、采用、导出和恢复的两轮证据另行记录。遇验证码、安全验证或人工登录立即停整个真实测试轮，等待用户处理恢复；不继续其他案例、模型或地图请求。
