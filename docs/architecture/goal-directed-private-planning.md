# 首次模型理解与有界业务工具循环（V4；兼容V3）

普通首页和继续对话的新提交使用 `PRIVATE_GOAL_AGENT_V4`。首次提交先保存原话、旅行与有限许可，状态为 INTAKE；规则解析仅用于暂定界面和额度分档，不能标为模型已理解。真实理解成功之前不派发小红书或地图。历史 V3、V2/会话 V1 的请求、失败、采用版和账本保持原义，兼容入口不回写历史。旧页面仍发送V3时仍按旧9/13或后续5次上限建立许可，不默默扩额。

## 理解与程序约束

`agent_contract.Understanding` 返回意图、逐字段原话引用及 Python 字符位置、简短可审计摘要。`agent.apply_intake` 只提交定位正确且类型合法的更新，重新校验 PlanDraft，保护锁定项目、预算、明确预约和截止条件。到达方式 arrival_transport 与当地 transport、driving、rental 分开；飞机到达不覆盖租车自驾。初次提交抛弃未证实的规则猜测，后续只更新明确陈述。QUESTION/HYPOTHETICAL 不得更新条件；混合句只能引用其中明确陈述的修正。语义由模型判断，程序检查引用、类型、冲突和锁；引用正确不等于语义必然正确。

单独填写的目的区域由程序持有，作为独立输入传入模型；不伪造它在原话中的位置。与原话冲突则停止澄清。未给出的机场、私址、人数、预算、日期仍未知。原话经现有敏感信息过滤后才出站，审计同时保留过滤输入摘要和能证明的原话位置；敏感或有歧义的定位不得提交。

V1理解协议的接收契约按`field`判别15个字段，不再允许任意字段与任意字符串/整数/布尔值交叉组合。JSON-object模式把同一判别schema放入生产system输入，schema模式发送同一结构；两种模式都在本地接收校验。天数1–90、人数1–100、参考预算0–100000000分均为严格整数，不把布尔或字符串当数字；未知可为null。驾驶/租车为YES/NO/UNKNOWN，到达AIR/RAIL/ROAD/UNKNOWN，当地交通和范围沿用PlanDraft枚举；步行才使用true/false/null。钟点必须HH:MM，日期必须有明确ISO日期与时间，并验证真实日历和前后关系。“这周”等相对说法不补造日期。

仅驾驶字段兼容原JSON布尔表示，规则`EXPLICIT_DRIVING_BOOL_V1`：类型必须恰为bool，原话定位有效、不是QUESTION/HYPOTHETICAL，并且引用为程序允许的明确自驾/不自驾陈述且极性一致；true转YES、false转NO。含假设、极性冲突、复杂或无法判断的说法停止接收，不宽泛truthy转换，不推断当地交通、租车或日期。兼容记录保留原布尔值、转换结果和规则编号；模型提示仍要求返回规范枚举。规范枚举仍不意味着自然语言语义已被外部事实核实。

接收错误区分INTAKE_SCHEMA、INTAKE_EVIDENCE、INTAKE_APPLY，诊断只保存已知字段、类型/枚举/范围/格式/依据类别及安全代码，不记录原始异常值。已实际请求或返回模型的记录、子任务ID、次数和HTTP诊断保留；任一更新非法时整组条件不提交，也不进入搜索。旧AGENT_STOPPED失败可按同scope/session/grant下的已存理解子任务只读展示具体原因，原状态、回复、用量和草稿不变，且不自动重跑。暂定结果、已生效条件和失败阶段在主页面分别显示。

## 工具与反馈

最多六轮监督决策，每轮为一次真实模型调用。模型只能选择下列业务工具，不能获得浏览器控制、Cookie、token、任意 URL 或供应商底层接口。

| 工具 | 作用及边界 |
|---|---|
| CACHE | 本地重新核实资料的有效性与用途，零外部调用 |
| DECOMPOSE | 仅整理已经采信的玩法、路线与取舍，保留作者角色、条件和作用范围，不重新审批 |
| RESEARCH_GAP | 当前缺口内一次搜索及一个有界正文批次；从同一已观察列表按每篇实际审核后的缺口及标题多样性重新选读，继续原严格提取和上下文审核 |
| GENERATE | 使用当前选择、排除、锁与合格引用生成一次可修改建议；有合格提议后本地结束，不再消费模型调用FINISH |
| ANSWER | 问题或假设的缓存回答，不改偏好、不查新资料 |
| KEY_LEG | 只在本次明确授权后，使用既有高德包装器核实一段有来源的公共衔接 |
| FINISH | 结合实际结果与缺口停止，程序决定 COMPLETED/PARTIAL/BLOCKED |

派发前持久保存决策；派发后保存实际状态、采信数量、前后覆盖和剩余额度。下一次模型输入包含这些真实反馈以及当前有效选择、排除、相关引用、条件、两段交通和锁。V4监督输入最多六个来源，明确选择及本任务新材料优先；每来源过滤后的必要引用与条件合计最多6000字，使用不含站点标识的source_ref区分来源。普通缓存问答仍最多两个来源。源文和工具文字都是数据，不可执行其中的指令。正文事实审核和逐方案校验不因工具选择而省略。空白占位、路线名称和未知交通仍不能成为完整攻略。

所有子任务共用一个grant与耐久操作账本。只有明确的新V4页面提交采用下面的有限契约；没有技术额度表单，不自动追加子许可，不修改旧许可、不退回已派发次数。

| 新许可 | 连接 | 搜索 | 正文 | 模型总额 |
|---|---:|---:|---:|---:|
| 首次同区域短旅行 | 1 | 2 | 4 | 13 |
| 首次三天及以上或区域旅行 | 1 | 3 | 6 | 18 |
| 普通后续明确更新 | 1 | 1 | 2 | 8 |

模型成本公式为`1次理解 + 每次搜索前1次监督 + 每篇2次提取/审核 + 1次结果反馈监督 + 1次规划`，即`2×正文上限 + 搜索上限 + 3`。缓存足够的理解→监督→生成仅需3次；问题/假设的理解→监督→缓存回答也是3次，不保证每次都使用全部额度。额外本地工具决策仍计入总额，可能降低可读正文数。

`agent.tools`在决策前先减掉本轮监督成本，执行时按已消费后的余额重新核对。正文批次大小取剩余正文、按剩余查询分配的正文数与`floor((剩余模型−本轮决策成本−2)/2)`的最小值。每篇读取前再次保留2次模型供反馈决策和生成；没有完成空间时不派发新正文。最后一轮监督不可再派发需要下一轮收尾的研究、本地整理工具。成功生成后按真实覆盖本地完成或部分完成，不额外请求模型只为FINISH。生成仍需有独立合格的活动引用，不为用完预留额度而编造内容。

旧V3已有许可和旧页面新建许可仍保持9/13、后续5的原上限；升级后的安全预留会阻止其无法收尾的新研究，不把旧许可自动变成V4。旧任务恢复不重新派发。V4改变的是新许可的明确上限与有界执行，不是本开发批次的真实访问授权。

多轮研究共享同一个owned reader，会话仅连接一次，详情编号沿用同grant累计值。单个有界批次内继续使用同一查询的列表，不为每篇强制重新搜索；每篇审核后重新择读，覆盖足够即停。列表只表示标题等元数据，正文次数独立显示。跨批次匹配原详情账本的指纹，空正文失败即使未建立来源行也不会再次选读；相同正文不再提取或增加覆盖，同查询重复决策也在派发前拒绝。task_view汇总本任务全部研究子任务及候选去重，不能只显示最后一轮。后续来源失败不能隐藏先前独立合格结果。遇到登录挑战、验证、限制、取消、失效、迭代上限、重复动作或额度不足停止；不自动重试失败调用。

## 地图、采用和恢复

地图默认额度0；首页独立勾选本次一段公共衔接才登记最多2次地点和1次路径，其他旧许可不变。程序验证公共来源、相邻同日对象、适用交通、当前 revision 与权限。候选地点必须用户确认，不自动选择 POI、不用驾车代替公交。需人工确认时循环停止；后续由既有关键路段页面显式操作，不宣称已自动完成整段。地图原始返回只存在服务内存，监督模型只收到状态，不得到坐标或真实地图响应。此交互仍不是全自动地图闭环。

新建议仅为待选提议，预览、取消、采用和导出使用原生产路径；导出同时区分到达方式和当地交通。重启只恢复已存结果或标记中断，不重新理解、不重派工具、不恢复额度。generation、父任务状态、当前 revision、输入绑定和引用有效性一起约束晚到结果。

SQLite仍为18，本轮没有数据迁移。既有索引允许agent/model/research-step在同一grant顺序执行，仅一个活跃子任务；历史普通研究仍单grant单job。domain/openapi的正常提交与会话许可枚举增加V4，保留V3。没有删除、转换或重新审核旧业务行。

## 验证界限

离线验收使用自编来源、受控 Reader/Amap transport、生产 worker 和真实 OpenAICompatibleProvider 序列化入口；所有外部 socket/DNS 被拒绝。它能证明流程、权限、输入与恢复，不能证明 DeepSeek 实际语义质量、真实小红书研究深度或高德时效性。本批不新增真实请求，G1保持原NOT PASS，真实质量为NOT_MEASURED。


上下文审核规则4区分明确读者邀请和作者未来计划，原提议及审核结果保持不可变。V2旧规则可由本地确定性回放生成独立版本，继续所有引用、事实及依赖检查，保留模型拒绝/待审；不转换V2字段，不创建外部模型请求，不将本地重校验称为模型审核或事实核实。

## 明确请求重新分析缓存正文

正常继续对话明确发送“用已缓存正文按当前住宿缺口重新分析”时，程序走 `CACHED_BODY_NEW_MODEL_ANALYSIS`；这与 CACHE/DECOMPOSE 的本地已采信引用整理、已保存回复的确定性复核不同。问题、假设、引述和否定不触发该入口。只绑定当前旅行可证明来源关系的最多两份 FULL_TEXT/PARTIAL_TEXT 快照，不从其他旅行、备份或被清理正文兜底。

准备阶段先核对当前缺口、正文哈希、规范化版本、来源策略及清理/撤回状态，再为这次明确提交建立新的有限许可；不改旧许可和账本。连接、搜索、详情与地图上限固定为0，模型最多8次或用户明确的更低上限，少于5次不开始。每来源每次继续现有敏感信息过滤与6000字上限，不发送整份档案。reference-selection-v1.2 标记新的提取输入契约，既有原文片段ID、定位算法、事实与上下文审核标准不变。

冻结绑定包含来源/内容ID、内容哈希、规范化版本、策略ID及版本、完整性、提取提示版本与缺口。相同旅行中已经实际尝试的相同快照、提示版本与缺口不再重试；新提示版本或实际变化的当前缺口，仍须新的明确请求。旧拒绝、失败和审核不回写。旧任务未尝试的第二份快照不冒充已消费。每份正文提取一次，随后独立模型上下文审核；后份失败不丢掉先前独立合格结果。新增内容继续现有证据、知识整理及规划路径，不以有效片段ID代替语义采信。

本地缓存可读不等于允许发送模型。准备、派发、提取子进程入口/HTTP开启前/返回提交前、审核预留与子进程同类边界，分别核对快照原策略和最新策略的外部推理权限，以及当前旅行、任务、generation、revision、有效许可与截止条件。撤销、取消、过期或晚到结果停止，不补额、不自动重试、不退回网站研究。缓存分析不会构造小红书 reader 或启动浏览器。

反馈分别记录本次真正新增的去重 Evidence、本次审核采信（可含已有重复）、当前可用资料与此前已有资料。不能用整个目的地既有 Evidence 数宣称重新分析改善。理解提示与程序依据检查也明确：不要求精确时刻/每天排满只是输出弹性，不能据此设定 RELAXED；节奏未知保持未知，历史误判不回写数据库。

此入口当前完成合成生产链、真实缓存只读准备及零访问部署验收；未发起真实重新提取/审核，真实内容质量仍 NOT_MEASURED，G1与既有内容缺口不变。阶段证据见 [缓存正文分析准备](../../reports/P10-cached-body-reprocess-readiness.md)。
