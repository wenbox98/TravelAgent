# 04｜攻略准确性与低请求研究策略

## 目标
在同一质量约束下减少不必要访问，而不是追求某个神奇的防封参数。优化对象包括搜索、详情、导航、自动重试、登录核实及媒体访问。不同用户/账号/日期的结果可能不同；不承诺固定调用次数即可覆盖任意目的地。

## 研究顺序
```text
理解当前决策层级
 → 查可合法复用的个人资料（先过滤权限与适用性）
 → 建立证据缺口表
 → 生成最少搜索问题
 → 搜索候选，不翻页扫全站
 → 基于现有元信息去重/排序
 → 逐篇读取最能补缺口的正文
 → 提取带来源的结论
 → 满足阶段需求即停止，或说明缺口
```

第一次需求的决策层是“路线方向/大概天数”，不是餐厅和房型。选定大方向后，第二次研究只补对应交通、活动或住宿片区。用户单纯把已有 AC 改成已有 ABD，不应自动重搜全目的地。

## 两层去重
搜索前：`account_scope + normalized_query + filters + purpose + temporal_scope + policy_version` 构成检索键。只合并语义确实相同的意图，“川西夏季徒步”和“川西国庆交通”不是同一查询。

搜索后：优先按平台 note_id 精确去重；无法取到 ID 才用规范化链接。对已读内容以归一化文本 hash 和相似度聚类识别转述/转载；同一作者的多篇内容不能直接算多个独立证据。独立性未知则标 UNKNOWN，不伪造作者信息。

搜索结果中的 token 不纳入持久化去重键。权限不允许缓存的来源只能在本次任务内复用；跨次任务不可为了命中率强行保存原文。

## 候选排序：仅使用已观察的字段
先做硬过滤：目的区域明显无关、内容不可访问、已读重复、时间/场景明确不适用。没有发布日期不自动淘汰，而是赋予 temporal_unknown。

设计初始权重（待评测调整，不是经验事实）：相关性 0.35、标题/摘要透露的具体性 0.20、用户约束契合 0.15、时间适用性 0.10、相对已选内容的差异性 0.20。

注意：只有标题时，“具体性”是预期收益，不是已确认正文信息量。点赞收藏数不作为事实可信度；只可在其他条件相近时辅助选择，禁止纯热门排序。避免全是一个路线/作者；通常对同一已知作者最多优先读 1 篇，需要补缺口时再追加。

可使用本地语义向量辅助排序，但只有允许推理/传送的数据才能进模型。结构化评分异常时退回确定性排序，而不是额外发起一轮平台搜索。

## 逐篇自适应读取
每读一篇后重算缺口，不预先并发打开整个 Top-10。选择下一篇依据 `expected_missing_slot_gain / estimated_visit_cost`，不用模型声称的“我很确信”直接停止。

粗略攻略证据槽位：区域组合、代表性体验、天数/停留范围、主要移动关系、适用季节/日期、取舍理由。用户第一轮缺人数/交通不影响前三类研究；涉及它们的结论标假设。

停止读取与研究完成分开判断。只有候选方向已有足够可追溯依据且关键缺口已解决或明确限制输出范围，才可判定本轮研究完成。连续两篇没有新信息只触发重新评估方向；仍有关键缺口时返回 PARTIAL，不表示研究成功。候选耗尽、预算用尽、用户取消、验证/拒绝访问分别记录原因，不得冒充完成；取消保持取消状态，验证/拒绝访问暂停账号。

至少两个独立来源簇支持的路线经验可作为粗略建议依据，但“两个来源”不是正确性证明；景区开放、预约、票价、道路安全等硬事实必须核对相应权威来源，查不到就保留待核实，不以多数经验代替。

## 初始调用预算（本应用的设计护栏，非小红书公布阈值）
| 范围 | 搜索操作 | 详情操作 | 图像补读 | 自动评论展开 |
|---|---:|---:|---:|---:|
| 首轮粗略攻略 | 3 | 6 | 2 张以内 | 0 |
| 用户已选方向的单轮补查 | 2 | 4 | 2 张以内 | 0 |
| 一次研究会话的累计硬上限 | 5 | 10 | 4 张以内 | 0 |

以上与 `config/defaults.json` 一致。3/6 是首轮及单轮 PoC 的最大护栏；补查采用更低的 2/4，两轮共享 5/10 会话累计上限，revision 不重置账本。这些上限均不是平台安全阈值。

图像补读从当前已取得的图像引用中选择；优先处理正文缺失的关键字段，不批量下载全部图集、不做视频转录。Vision 请求与图像网络读取分别计数。无权处理图像或无模型能力则标记未读，不伪造文字。

同账号并发=1；正常研究操作间隔初值 8 秒，用于降低本应用负载而非模拟人类/保证免风控。发现平台明确更严格的指示时服从；遇挑战立即停止，不靠调整间隔继续冲击。

预算必须覆盖失败、重试、用户多次点击、任务恢复、不同 Agent 节点。先原子预留 permit，再访问，完成后记账；已经发出的失败请求也消耗预算。未访问前被校验拒绝才退回预留。详情里隐式导航重试不能被遗漏。

同一研究会话的预算不随消息、job 或 revision 自动清零。用户可通过明确的“追加一次研究预算”操作新增有限额度，UI 展示变更；禁止模型自己追加、把一条任务拆成十条规避上限。

## 请求统计口径
| 指标 | 定义 |
|---|---|
| search_ops/detail_ops | 本应用发起的上游业务操作，含失败 |
| auth_probes | 真正触达平台的登录状态核实 |
| page_navigations | sidecar 页面导航与重试次数 |
| site_http_requests | 浏览器可观察到的平台/相关资源请求数，注明覆盖范围 |
| image_fetches/model_calls | 图像抓取和模型调用，分别记录 |
| unique_notes_read | 成功取得正文的去重笔记数 |
| duplicate_fetches_avoided | 本应重复读取但在访问前被合并的数量 |

一次工具调用可能引发很多网页请求。若当前 sidecar 不能完整观测网络，`site_http_requests=null`、`network_measurement=UNAVAILABLE`，不能写 0。页面/CDN/验证码框架的请求按类别统计，不记录完整 URL 的 token、cookies 或响应正文。不要为了减少计数去阻断平台安全组件。

## 缓存与失败处理
允许保存的内容按来源用途、适用时间、处理版本和模型版本复用。TTL 是本应用新鲜度策略，不是权利许可；权限收回立即无效。账号变化要隔离查询结果与 locator。新鲜度未知不能在比较时自动当成最新。

同一任务内对明确删除/不可见笔记做负结果缓存，防止反复请求；认证失败不缓存为“笔记不存在”。网络未知可以最多一次外层重试，不做上游+SDK+worker 三层指数重试。

## 评测方法
离线固定候选池和完整标注，将“每个查询直接读前 10 篇”的基线与本策略比较。基线仅在合成/允许复用数据回放，不为了比较而额外扫真实站点。

指标：有效正文精确率、关键槽位覆盖、来源支持率、地域/季节错误率、重复阅读率、在相同证据质量下的逻辑操作节省率。来源支持由人工逐条审查，不能让同一个模型既生成又独自判定自己满分。

设计门槛：离线有效正文精确率≥80%；关键事实来源支持率≥95%；已声明的硬约束违规=0；预算超发=0。请求节省目标≥30% 仅是有质量底线的离线目标，尚未测得；真实使用单独报告分布，禁止宣传“减少 X%”而没有报告。

## T04 实施细化

同时阅读 [16｜小红书筛选实施细则](16-xhs-screening-spec.md)。未知条件不参与偏好加减分；排序不预读全部正文；记录候选筛选理由、实际补齐的信息和停止原因。新增测试是设计，不是已执行结果。

## v1.1 Evidence Gap 与复用优先
每次研究先执行 `Reuse → Gap → Search → Select → Read → Extract → Re-evaluate`。第二次用户增加“只有5天、不想自驾”时，先从 SQLite/个人资料库找仍适用 Evidence；只有“非自驾可行性”等缺口无法回答时才新增搜索。严禁为了让答案看起来更新而重跑第一次全部关键词。

PoC 默认上限为 `max_search_operations=3`、`max_feed_details=6`，但满足当前决策所需证据后立即停止。预算耗尽且关键缺口仍存在时返回 `insufficient_evidence=true` 和缺口清单。搜索操作数与浏览器真实网络请求数不是同一个指标；无法完整观测后者时必须标 `UNAVAILABLE/PARTIAL`，不得把操作次数冒充 HTTP 请求次数。

候选选择优先考虑：当前 research_question 相关性、地点匹配、路线/时长信息潜力、对已有证据的增量、与已读内容重复程度、当前 Evidence Gap。热度只能作弱信号。
