## 2. 根因、原判定和 CHECKING

旧实现先在官方页面检查验证特征、登录弹窗和登录按钮，再要求 `.main-container .user .link-wrapper .channel` 有可见匹配，才继续读取 `window.__INITIAL_STATE__.user.userInfo` 中的登录状态/账号 ID。

真实页面已正常登录，`userInfo.value` / `userInfo._value` 存在明确 `guest=false` 和可用账号 ID，但旧入口没有可见匹配，于是旧逻辑提前返回 UNKNOWN。状态机把 UNKNOWN 映射为 CHECKING，真实认证信号尚未读取就被阻断。

“旧 selector 失效”准确指**可见性前置条件在当前页面不成立**，不应等同于选择器完全没有节点。本轮只读形态探测找到旧选择器 2 个节点，而实际 detector 仍报告没有可见匹配；自我导航链接有 1 个，其中带头像 img 的数量为 0。因此没有凭空添加头像选择器。

原流程已有 240 秒总登录时限，不能称正常情况下真的无限循环；问题是证据不足仍长时间 CHECKING，且缺少明确的观察停止原因和安全诊断。新版增加连续 UNKNOWN 时限和观察次数上限，并测试晚到认证结果不会越过截止时间。

## 3. 新的多信号判定

新增独立 `LoginEvidence` 和 `classify_login_evidence()`；`LOGIN_OBSERVATION_SCRIPT` 只读取同一页面当前 DOM、路由和现有页面状态，不 fetch、不刷新、不导航、不打开账号主页。

| 类型 | 采集与判定 |
|---|---|
| origin / 路由 | 只接受既有官方 HTTPS origin；分类为正常 explore、其他官方路由、登录、验证、外国 origin 或未知。当前仅正常 `/explore` 路由可以认证 |
| 页面加载 | 页面完成加载后才考虑 AUTHENTICATED |
| 登录反向信号 | 沿用现有 `.login-container, .qrcode-img` 和 `.login-btn` 的可见性；弹窗、按钮、登录路由或明确 guest=true 任一存在即 LOGIN_REQUIRED |
| 验证/限制 | 保留现有 captcha/verification DOM 与路由检测；读取可见 dialog/alert 与页面标题中的验证/访问限制特征，仅输出布尔值。优先 VERIFICATION_REQUIRED 并暂停观察 |
| 明确用户状态 | 支持 `userInfo.value`、`userInfo._value`、直接对象；严格 guest=false 为正向认证信号，任何 guest=true 冲突优先 |
| 当前实测的个人入口 | 可见的正常 `a[href]`，文字为“我/我的主页/个人中心”，指向同 origin 的 `/user/profile/<id>`；不点击，不把链接原文带入诊断 |
| 入口 fallback | 页面用户状态没有明确 guest 标志时，个人入口必须与同页可靠账号 ID 一致才可作为正向认证证据。普通他人主页链接、无匹配 ID 的入口不算成功 |
| 旧账号入口 | 仅作为 `legacy_account_entry_present` 诊断，绝不再阻断用户状态提取 |
| AccountIdentity | 同页候选 ID 必须格式有效且唯一；冲突或无法可靠读取时为 UNKNOWN。ID 仅在本机私有内存中，公开状态只给 KNOWN/UNKNOWN |

认证必须同时满足：官方正常页面、加载完成、验证/访问限制/登录提示均明确不存在，以及至少一个正向认证证据。单独没有弹窗、URL 改变、出现 ID 或账号链接，均不能判 AUTHENTICATED。明确 guest=false 无须依赖可用 ID，身份未知不阻止确定已登录。

默认同页轮询间隔 0.5 秒，每流程最多 480 次；连续 UNKNOWN 最多 30 秒，正常等待登录最多 240 秒。证据不足进入 ERROR / LOGIN_STATE_UNCERTAIN，给出 OBSERVATION_TIMEOUT 或 OBSERVATION_LIMIT；总登录超时使用 LOGIN_TIMEOUT。配置拒绝 NaN、Infinity、非正数和无限次数。失败不自动重新打开浏览器或导航，status 不触发重试。原生驱动单次等待仍有 20 秒上限；这些边界不保证故障进程能在精确毫秒退出，但应用观察不会无限 CHECKING。

公开诊断只包含固定分类、布尔值、观察次数及 stop_reason；账号 ID、Cookie、token、二维码、完整 URL 和原始页面状态不进入日志或 API。generation、取消、退出和清理顺序继续防止旧回调恢复登录状态。
