## Root cause

| 结论 | 证据与边界 |
|---|---|
| CONFIRMED：旧路径规则存在不一致 | 旧 Python 要求最终路径完全等于 locator 初始路径；JS 接受相同 ID 的两种路径。上一轮已将 Python 修正为同一白名单，本轮保留该修复。 |
| CONFIRMED：本轮发生合法路径变化 | 初始 DETAIL_SEARCH_RESULT，最终 DETAIL_EXPLORE；同一 note ID，main document 200，HTTP 主文档重定向链计数 0。旧的严格路径相等条件会拒绝本轮这种变化；当前已正确接受。 |
| LIKELY：旧失败与路径变化有关 | 新实测支持这个解释，但本轮读取的是上一轮未访问的备用候选，并非原失败来源，不能倒推历史现场。 |
| UNKNOWN：上一轮具体拒绝分支 | 旧进程没有保存分支/最终路径诊断，无法确证当时是路径检查还是导航后的 guard。1.174 秒窗口只提示可能发生在后置等待前，不能当成根因证明。 |

当前合法详情是官方 HTTPS origin 下 `/explore/<相同id>` 与 `/search_result/<相同id>`，最终路由允许单个末尾斜线。没有新增 `/discovery/item/<id>` 支持，也不把任意官方页判为详情。SourceIdentity 与 AccessLocator 分开；403、空 state、缺正文不自动推断 token 过期，TTL 仍 UNKNOWN。

本轮增加独立 DetailPageEvidence，以 route、内部 noteId、多项标题/正文/作者/图片信号、明确不存在登录与验证来保守判定。分类包含 DETAIL_EXPECTED、LOGIN_REQUIRED、VERIFICATION_REQUIRED、ACCESS_DENIED、NOT_FOUND、REDIRECTED_OTHER_VALID_XHS_PAGE、ACCESS_LOCATOR_INVALID、IDENTITY_MISMATCH、UNEXPECTED_PAGE、UNKNOWN；没有改公共 HTTP 契约。

另确认并修复 `_observe` 使用缓存版 urlsplit 导致完整访问 URL 可能留在全局解析缓存的问题，改为无缓存解析。这是内存生命周期风险修复，不是发现真实 token 已进入日志的证据。

## Completeness 与正文 locator

结果 **PARTIAL_TEXT**，reason=`unverified_or_truncated_text`。已取得非空正文且 DOM 正文容器存在，但 DOM 文本与 state 正文不完全一致；是否存在待展开/截断仍为 UNKNOWN。没有额外滚动/点击/刷新证明完整，因此不升级 FULL_TEXT，也不推断两份文本为何不同。

## Conclusion

1. 本轮一篇正常图文详情技术链路 **PASS**，A～G 条件满足；范围不外推到视频、已删除/受限笔记或所有页面版本。
