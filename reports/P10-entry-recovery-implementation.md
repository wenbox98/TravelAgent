## 真实复现、修复和实际结果

用户当前 Edge 的普通 `http://127.0.0.1:8768/` 页面有未提交想法，但“查看本地草案”禁用；点击“重新读取本机状态”仍失败。初始化 API 未通过时 App 将默认 productFlow=false 当成旧产品，从而出现可输入、不能继续的旧表单。只核实到缺少有效本机会话，未断言 Cookie 过期的具体原因。

修复后该同一标签使用明确的连接状态界面。本机 `serve --open` 在原服务已运行时成功重开入口，PID 3848 前后保持一致；原标签重新连接后保留原句，“开始规划”启用。实际点击创建 1 个独立本地旅行，正确识别目的区域和 7 天，交通仍未知；本地适用资料为 0，页面给出查看本地玩法、查看有限研究许可两个下一步，没有编造路线。刷新后同一旅行恢复。未开许可，未点击外部研究、模型或地图。

旧页面没有未提交保存机制；部署前记录原控件值，部署后通过正常输入控件恢复原句。新版本的刷新/断线保留由浏览器本机未提交副本实现，不把这次人工迁移称为旧版本已有能力。

## 生产位置与规则

- `App.vue::load`：loading/ready/auth_required/offline/error；初始化失败不再显示旧预览，原因紧邻提交；明确的安全重开说明与重连按钮。历史门禁移入可展开说明，仍保留真实限制。
- `api.ts::RequestError/request/readIndex`：保留 code/status，区分离线与服务错误，15 秒本机 HTTP 等待上限；超时说明结果可能已保存，不能自动重发。检查初始化响应字段，不将损坏响应当 ready。
- `TripIntake.vue`、`intake.ts`：一句话主输入、可选目的区域修正、明确“开始规划”；Ctrl/⌘+Enter 排除 IME composing/229；提交期间及父级 busy 阻止重入。未提交内容只在当前浏览器本机保留，成功后清除。
- `planning.intake.destination_from_idea`、`PlanningService.create`：通用明确区域提取；歧义要求修正，不按目的地或旅行 ID 特判。复用原天数/驾驶解析，来源校验与建议型规划要求未放宽。
- `PlanningPanel`：正常创建默认仍知识优先；空活动草稿有识别摘要和缺资料下一步，避免先展示空攻略与空地图。轮询错误可见；增加父级未保存/切换检查及保存响应期间的新编辑保留。复杂活动子表单的全部编辑竞态尚未完成实测，不能宣称已解决。
- `preview.local_entry.EntryTickets/entry_proof`、`preview.api.install`、`product_preview.reopen`：本机启动器用私有工作区密钥证明身份，为同一服务签发有界的一次性入口；拒绝网页 Origin、非 loopback、错误 Host、错误证明与查询参数。保留 Cookie/CSRF/Origin/幂等检查；过期 HTML 链接回根页面，API 保持 401。不停止服务、清库或创建额度。

契约：`PlanCreate.destination` 可省略，歧义返回 422 DESTINATION_REQUIRED；domain schema 同步生成。启动器内部 `/local-entry` 协议与 bootstrap 的安全要求记入日常工作台架构，不暴露为业务工具。无数据库迁移或外部许可变更。本批使用明确的契约变更提交。
