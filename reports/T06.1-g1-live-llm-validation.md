本地受限诊断确认官方主机 `api.deepseek.com` 的 path 为 `/anthropic`，没有外围空白。代码追加 `/chat/completions`，形成与所选协议不匹配的路径；这与观察到的 404 一致。DeepSeek 官方区分 Anthropic 根地址 `https://api.deepseek.com/anthropic` 与 OpenAI 兼容根地址 `https://api.deepseek.com`，项目需要后者。没有修改地址后再次请求。[官方协议说明](https://api-docs.deepseek.com/guides/anthropic_api/)；[兼容调用示例](https://api-docs.deepseek.com/guides/json_mode/)

另有独立能力差异：代码固定发送 `response_format.type=json_schema`，官方 Chat Completions 参数只列 `text/json_object`。这是文档核对结果，不是本次 404 已实测的根因；正确地址下尚未测试。下一次继续前，需要在现有 provider 内明确输出能力并保留本地严格 schema/grounding 校验，补离线回归，不能只修改 prompt 或放宽验收。[官方参数](https://api-docs.deepseek.com/api/create-chat-completion/)
